Technical reference

Architecture and deployment scope

What the system enforces, where data lives, and the boundaries of the deployed architecture.

Privacy and versioning

The browser communicates with an authenticated Node.js API. Profiles and supporting evidence are encrypted using AES-256-GCM in a SQLite vault. A keyed HMAC index matches normalized document identifiers. Salted SHA-256 commitments, previous-version links and verification state are recorded in a Solidity registry.

Exact matching only identifies the same document within its country and document type. It does not infer that different documents belong to the same person. Account names, email addresses, operational metadata and off-chain audit records are not encrypted profile snapshots.

Consent and transactions

The linked customer approves version-specific sharing through an authenticated session. The backend relays the consent attestation using the issuer's key. The registry enforces membership, issuer ownership, version sequencing and consent requirements for reuse. A durable outbox reconciles confirmed blockchain transactions with pending database updates after an interruption.

Hosting protections

The deployment uses HTTPS, secure session cookies, CSRF and origin checks, persistent session expiry, login throttling, first-login password replacement, a private data directory, a restricted application container and consistent scheduled backups. Sample accounts are not seeded in production mode.

Architecture limitations

The hosted Ethereum environment is a private Besu QBFT network with a single validator. Local training uses a development node. Institution keys are controlled by the application server. It does not provide independent institutional validators, customer wallet signatures or protection against a malicious host administrator. Manual officer verification is not automated document authenticity checking.

This is a hardened self-hosted pilot, not a certified banking KYC service. A single-validator network does not provide Byzantine fault tolerance. Independent key custody, production consortium infrastructure, externally reviewed identity-proofing controls and security/compliance assessment remain necessary before handling regulated real-world KYC operations.

Revocation blocks future application access; it cannot delete copies already downloaded. Read audit events are stored off-chain and are not described as immutable.
